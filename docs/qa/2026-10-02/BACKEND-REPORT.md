# Backend QA pass

PR: opened by orchestrator

CI status: pending at time of writing

## Outcome

Nine reproducible functional findings: Critical=0, High=5, Medium=3, Low=1. Independent security findings are reported by the Security pass. Three additional route-level repros corroborate FE-001, FE-002 and FE-003 and count only in the Frontend group.

Product code remains unchanged. Four files under `tests/qa_backend/` add 43 cases. The completed expanded run passed **24 tests with 19 strict expected failures**. Each expected failure requires `AssertionError` and names its finding ID; unrelated runtime failures are not accepted. A deliberate diagnostic run with `--runxfail` produced exactly 19 failed assertions and 24 passes, exposing the actual behavior in a readable report. The final normal run is linked in `BACKEND-SESSION.md`.

## Scope, methods, and charters

Risk-based focus was the API job lifecycle, result integrity, configured bounds, cache replay and workflow order. Fast in-process ASGI contract tests and mocked transport unit tests dominate the pyramid; the separate frontend/UX passes cover browser interaction. No target URLs were fetched. All tests ran with `pytest-socket --disable-socket --allow-unix-socket`. Local SQLite files and exports were created only under pytest temporary directories. Application dictionaries, locks and pending jobs are isolated and cleaned up per test.

BE-A charter: create/read/run/results/delete and malformed requests, timeboxed at 20 minutes. Positive controls cover explicit safe IDs, duplicate creation, unknown jobs, invalid input, API schema availability and result page boundaries. Eight simultaneous run requests produce exactly one accepted run and seven rejected duplicate starts. Deletion cancels a running task.

BE-B charter: data completeness, terminal states, cache replay, configured limits and DAG ordering, timeboxed at 20 minutes. The concurrency experiment shortens only the existing idle timeouts, confirms the item was processed, then observes that the worker group cannot finish. A deterministic Hypothesis property checks 50 combinations of URL-pattern start/page count. HTTPX MockTransport validates 200, retryable 503, non-retryable 400 and exhausted retry behavior. JSON, NDJSON, CSV and SQLite round trips preserve Unicode, commas, quotes, embedded newlines and zero values.

These were bounded exploratory charters, not claims that each consumed its entire timebox. UTC commands and outcomes are in [BACKEND-SESSION.md](BACKEND-SESSION.md). Static analysis, package installation/build and dependency review are coordinated separately and are not duplicated here.

## Frontend corroboration

These are strict expected failures in `test_api_contracts.py`; count them only once under Frontend.

## Existing suite and coverage

The baseline existing suite was run before any QA tests were added: **140 passed, 11 failed, 18 errors in 6.65 seconds**. No pre-existing failure was skipped, marked expected, or otherwise changed. Eighteen errors originate in the existing cache fixture supplying a string database path to a constructor expecting a Path directory; its teardown also assumes a nonexistent close method, so blindly fixing the first fixture error would not establish parity. Eleven ML test failures reflect score-scale/report-shape/public-method mismatches and an outlier expectation. These are existing suite debt, not nine extra product findings.

## Remaining limits

No real scraping targets, live proxies, browser-fetcher launch, credentialed LLMs, cloud storage, remote databases, alerts, distributed multi-process jobs, long-running memory/load measurements, or production deployment were tested. Request retry classes were tested locally, but large concurrent retry storms and cancellation races after job deletion/recreation remain untested. The API contract checks validate core schema and main routes rather than fuzzing every OpenAPI operation. Native auth mechanisms and URL/export trust boundaries are assessed in the separate security lane. This pass does not establish release readiness: ordinary and concurrent job execution are both blocked by confirmed defects.
