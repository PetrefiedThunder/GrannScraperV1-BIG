## Scope and execution

Independent UX pass on `qa/2026-10-02-sweep`, initial HEAD `30eb7c4`. Repository identity, worktree, branch and plan were checked before edits. All commands and failed attempts are in [UX-SESSION.md](UX-SESSION.md). No product code was changed.

The actual dashboard HTML and JavaScript were served on loopback port 8766. API responses were intercepted in the browser using fictional jobs and `example.invalid` URLs; every other origin was blocked. The harness reproduces the real `/static/index.html` and `/static/app.js` paths. **This is a downstream UX inspection using `/static/index.html`; the broken application root asset route is separately reported as FE-001.** No screenshot proves the default root route works. All owned browser contexts were closed; the shared browser server was not closed.

The browser connected to the supplied remote endpoint; no browser was launched or installed. UX evidence uses Chromium 153.0.8010.12 at 1440×1000, 375×812 and 320×812 CSS pixels. Cross-browser functional checks belong to the Frontend pass. Axe-core 4.13.0 ran WCAG 2 A/AA, 2.1 A/AA and 2.2 AA tagged rules in empty, completed-results and API-error states. ARIA snapshots and keyboard operation were reviewed alongside screenshots.

The timeboxed exploratory charters targeted accessibility/keyboard (20-minute ceiling), mobile/error/result recovery (15-minute ceiling), and onboarding (10-minute ceiling). Checks completed within those ceilings; they were not full-duration user studies. Risk priority was access to the main scraping flow and retrieval of its results, then reliable error recovery and quickstart accuracy.

## Nielsen heuristic review

| Heuristic | Observed behavior and assessment |
|---|---|
| Visibility of system status | Button progress labels and loading spinner exist. Global counts refresh, but job-list errors do not recover; live announcements are missing (UX-003, UX-006). Running detail text tells users to Refresh. |
| Match between system and real world | Website URL, Maximum Pages and Export Format are recognizable. “Has Results”, internal job ID and “Use concurrent scraping (10x faster)” are less useful to beginners; 10× is not established by this QA. This copy is an observation, not a separate counted defect. |
| User control and freedom | Close and native deletion confirmation exist. Focus after Close is hidden (UX-004). No in-dashboard path retrieves all data (UX-005). |
| Consistency and standards | Native form controls have labels and work with keyboard. Errors appear in duplicate and quickstart commands disagree with implementation (UX-003, UX-008). |
| Error prevention | Required URL, native URL validation and page-count min/max exist. FE-002/FE-003 separately cover values not honored by the backend contract. |
| Recognition rather than recall | Empty state suggests starting a scrape. Stored jobs show names, URLs and dates. README file-path versus saved-name ambiguity requires knowledge outside the quickstart (UX-008). |
| Flexibility and efficiency | Keyboard traversal is linear and predictable through the form; SDK exposes bulk result retrieval, but the dashboard lacks it (UX-005). CLI saved-job discovery fails (UX-007). |
| Aesthetic and minimalist design | Desktop form hierarchy is clear. Four large stat cards precede the form on mobile; horizontal job-row overflow prevents a clean narrow layout (UX-001). |
| Help users recognize, diagnose and recover from errors | Error text is visible, but disappears without announcement and job-list recovery has no control (UX-003, UX-006). README missing-job invocation prints a failure while reporting success to the shell (UX-008). |
| Help and documentation | README, Getting Started, examples and CLI `--help` exist. Help, cancellation and a valid saved-job invocation pass local checks; the main custom-config quickstart is stale (UX-008). SDK quickstart method names exist, but no real server/scraping call was made. |

## Reproduction and remaining limits

Browser tests import `@playwright/test` and `axe-core` through standard Node module resolution; dependencies can be installed locally or supplied through `NODE_PATH`. The sweep used the isolated public-package installation recorded in the coordinator log. Required remote endpoint: `PW_TEST_CONNECT_WS_ENDPOINT`; no `launch()` fallback exists. The exact logged browser invocation is in [UX-SESSION.md](UX-SESSION.md). Run the config at `tests/qa_ux/playwright.config.cjs`; it owns loopback port 8766 for the duration of the run. Python checks use `pytest tests/qa_ux/test_cli_docs.py`; `--runxfail` is only for deliberate defect reproduction and must not be used for a green regression run.

No production system, credentials, billing, cloud/database export, real scraping target, or real third-party API was contacted. No .env or credential file was read. No PR, commit or push was performed. Real screen-reader speech, touch hardware, OS high-contrast settings, actual browser zoom and sustained human usability studies remain untested. Body-font enlargement and ARIA snapshots are explicitly limited proxies. Axe reports include incomplete checks; they must be reviewed before claiming WCAG compliance. UI fixture tests do not prove the backend works; API integration and deployment are outside this pass.

Recommended UX fix order: narrow-layout access (UX-001), announcements/focus/contrast (UX-003, UX-004, UX-002), full-results retrieval and recovery (UX-005, UX-006), saved-job command and documentation accuracy (UX-007, UX-008). Resolve FE-001 first so these flows load at the intended dashboard URL.
